# Контроль запчастей: запуск на Bothost

Новый раздел выключен по умолчанию. Старые настройки контроля чатов сохраняются.
На рабочем сервере эту версию ещё не проверяли. Не запускайте вторую копию с рабочим токеном.

## Перед обновлением

1. Сохранить резервную копию действующей базы `DATABASE_PATH` и настроек Bothost.
2. Проверить, что каталог базы сохраняется при пересборке приложения.
3. Загрузить приватный `parts_fleet.json` в этот постоянный каталог. Не публиковать его в GitHub.
4. Установить `PARTS_FLEET_PATH` в абсолютный путь этого файла и `PARTS_ENABLED=true`.
5. Сохранить прежние `BOT_TOKEN`, `DATABASE_PATH`, `LEADER_USERNAME=Fedos_AV`.
6. Выполнить обновление единственного рабочего процесса. Команда запуска прежняя: `python main.py`.

Пример путей, только если `/app/data` действительно подключён как постоянный каталог:

```env
DATABASE_PATH=/app/data/bot.sqlite3
PARTS_ENABLED=true
PARTS_FLEET_PATH=/app/data/parts_fleet.json
```

Новая база создаётся рядом: `bot.sqlite3.parts`. Её тоже включить в резервное копирование.
Внутри хранятся заявки, история, незаконченные диалоги, группы, цифровые ID и очередь уведомлений.
При временном отказе Telegram уведомление повторяется. Редкий дубль возможен при падении процесса
между успешной отправкой сообщения и записью результата отправки; данные заявки не теряются.

## Однократная привязка

Руководитель отправляет в группе ДТП `/parts_bind source`, в группе закупа `/parts_bind target`.
Эти команды выполняются только руководителем и не показываются в меню менеджеров.
Привязка использует реальные номера групп. После привязки старый обработчик сообщений
не обрабатывает новые сообщения этих двух групп. Старые обращения, созданные до привязки,
следует проверить и завершить отдельно перед включением нового режима.

Все сотрудники открывают личку с ботом. Существующие известные ID переносятся из старого хранилища.
Если сотрудник сменил аккаунт, его ID нужно обновить отдельно: повторное использование ника
другим аккаунтом не даёт автоматического доступа. Руководитель также закрепляется по ID.

В группе закупа вручную отключить отправку сообщений обычными участниками после проверки личных сценариев.
Не давать менеджерам права администраторов, позволяющие обходить ограничения отправки.

## Правила

- 98 автомобилей, 97 назначений. Одна машина без менеджера требует решения руководителя.
- Изменения CRM автоматически не поступают. Для обновления нужен новый приватный справочник и перезапуск.
- «Машина не моя» меняет ответственного только в заявке. Справочник меняется отдельным обновлением.
- Первичный ответ: два рабочих часа, Пн–Пт 09:00–18:00 МСК; праздники отдельно не учитываются.
- После срока первого ответа руководитель получает отметку при ближайшей проверке (до 30 секунд).
- Последующие напоминания: Пн–Пт 10:00 и 16:00 МСК. После простоя отправляется одно актуальное напоминание.
- Полный заказ с оплатой, завершённый ремонт и отсутствие необходимости ремонта требуют подтверждения руководителя.
- Список запчастей одним текстом. Повреждения из источника доступны по ссылке; фото и архивы не скачиваются.
- Неизвестный номер либо неоднозначное повторное ДТП попадает в раздел руководителя «Требуют уточнения».
- Повтор по тому же номеру и дате ДТП дополняет прежнюю заявку, в том числе закрытую.
- Разрешение ремонта по нескольким машинам создаёт отдельные уведомления, без новых заказов.
- Обработка свободного текста использует ограниченные правила, не нейросеть. Необычные формулировки нужно проверять на реальных примерах.

## Приёмка на сервере

1. У менеджера только личные заявки и просроченные; чужая ссылка не даёт доступа.
2. Архив с номером и датой создаёт карточку; повтор с той же датой не создаёт дубль.
3. Без даты при существующем ДТП требуется выбор руководителя.
4. Частичный заказ остаётся активным; обязательны остаток/комментарий и дата.
5. Все три причины завершения доступны к подтверждению только руководителю.
6. Переназначение доступно текущему менеджеру; Влада в списке нет.
7. Просрочка отмечает руководителя; ожидание оплаты не отмечает Влада.
8. После перезапуска сохраняются карточки, сроки и незавершённый ввод.
9. В других рабочих чатах прежний контроль ответов продолжает работать.

Откат: `PARTS_ENABLED=false`, перезапуск. Новые данные остаются на диске.
Для полного восстановления прежнего меню удалить персональные команды для менеджеров,
установленные новым разделом; это не влияет на доступ к данным.
